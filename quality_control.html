Quality control of the bam files

First we use the information in the header to get information about the contents of the bam file and how it was generated.

NoteWhy QC matters for cancer variant calling

In somatic variant analysis, we’re looking for variants present in tumor but not normal tissue. These are often present at low allele frequencies (especially in heterogeneous tumors or with contamination). Therefore:

  • Coverage depth matters: Low-frequency variants (5-10% VAF) need >100x coverage for reliable detection
  • Duplicate marking is critical: PCR duplicates can create false variants or inflate allele frequencies
  • On-target rates: Poor capture efficiency means lower power to detect somatic mutations in genes of interest
  • Contamination: Normal cell contamination in tumor samples dilutes somatic variants
ImportantExercise 1

Check out the contents of the headers of the bam files with samtools view -H, and answer the following questions:

  1. How is the bam file sorted?
  2. Which chromosomes were used as reference?
  3. How many read groups are in there, what is the readgroup ID and what is the sample name?
  4. Which aligner was used?
  5. If there are duplicates in there, how are they marked?
  6. Which other programs were run to create the bam file?

  1. From the @HD tag, we can see that the bam file is sorted by coordinate.
  2. We have two lines starting with @SQ, which gives us information about the reference used. The reference genome used contains chromosomes 6 and 17.

  4. In order to know which programs were run to generate this bam file, we can use the @PG tags. Here, we see that the aligner used was bwa mem
  5. The duplicates were marked with MarkDuplicates.
  6. To sort the alignments samtools sort was used. For base quality score recalibration (BQSR) GATK ApplyBQSR was used.

Now we extract information from the alignments themselves. We first have a look at few alignments and then get a summary of the alignments with samtools flagstat.

ImportantExercise 3

Create a script called 01_samtools_flagstat.sh and store it in ~/project/scripts. Use samtools flagstat to summarize the alignments in both bam files. How many reads are in the bam files? And how many alignments are marked as duplicate?

NoteCheck your result

Before moving on, compare your numbers with these:

Metric Normal Tumor Acceptable
Mapped 99.43% 99.45% > 95%
Duplicates 11.0% 11.2% < 20-30% for exomes
Properly paired 98.30% 98.43% > 90%

A low mapping rate points to contamination or the wrong reference. A high duplicate rate means low library complexity: fewer independent reads support each variant.

So, all looks good until now. We have many reads and high alignment rates. The bam files seem to be ready for variant analysis, because they have read groups, duplicates are marked and they are sorted by coordinate. However, since we are working with whole exome sequencing (WES) data, we would like to know whether the reads align to the target regions and what kind of coverage we have. For this, we use gatk CollectHsMetrics.

ImportantExercise 4

Create a script called 02_gatk_collecthsmetrics.sh in ~/project/scripts to run gatk CollectHsMetrics on the two bam files. Here’s an example:

PROJECT=~/project/alignments
ALIGNDIR=~/project/data/alignments
REFDIR=~/project/data/reference

mkdir -p $PROJECT

for sample in tumor normal
do
    gatk CollectHsMetrics \
    -I "$ALIGNDIR"/"$sample".recal.bam \
    -O "$PROJECT"/"$sample".recal.bam_hs_metrics.txt \
    -R "$REFDIR"/ref_genome.fa \
    --BAIT_INTERVALS "$REFDIR"/exome_regions.bed.interval_list \
    --TARGET_INTERVALS "$REFDIR"/exome_regions.bed.interval_list
done

The produced reports are not so easy to read. We also run fastqc on the two bam files. FastQC works on bam files too and gives general quality plots (base qualities, GC content, read lengths, duplication levels). It writes into the same folder (it takes about 1 minute):

PROJECT=~/project/alignments
ALIGNDIR=~/project/data/alignments

fastqc -t 2 --outdir "$PROJECT" "$ALIGNDIR"/tumor.recal.bam "$ALIGNDIR"/normal.recal.bam

To parse the metrics files and the FastQC reports together, we run multiqc on the directory:

MULTIQC=~/project/multiqc
PROJECT=~/project/alignments

mkdir -p $MULTIQC

multiqc $PROJECT -o $MULTIQC

Download the multiqc report (multiqc_report.html) by right-clicking on the file and select ‘Download’. Check out the hybrid-selection metrics or by clicking here: multiqc report . How did the hybrid capture go? Are most bases on-target? What kind of coverages can we expect in the target regions?

The FastQC reports (tumor.recal_fastqc.html and normal.recal_fastqc.html) are in ~/project/alignments. MultiQC shows them as the FastQC section. For comparison, here are the reports of the two samples: tumor fastqc report and normal fastqc report .

Note

You can find the documentation on the different metrics here. Note that the descriptions of the metrics are not always correct. The metrics with ON_BAIT contain information including duplicates, while ON_TARGET without duplicates. This has been an issue since 2020, and has not been fixed so far.

TipAnswer

We see that we have a fold enrichment of around 22 and about 45% usable bases on-target. About 90% were ‘selected bases’, which means bases aligning within 250 bp of the target region. We’re looking at a de-duplicated coverage of 84x for the normal sample and 114.9x for the tumor sample. So, on average, we seem to have acceptable coverages for both samples.

In the FastQC reports, Total Sequences (12,744,793 for normal and 16,674,562 for tumor) is the same number as samtools flagstat gave, so duplicates are still counted. Base qualities, per base N content and adapter content pass. The warnings for Per sequence GC content and Sequence Length Distribution are normal here: the capture of exome regions gives a GC distribution that differs from the theoretical one, and the reads do not all have the same length (30 to 100 bp).

Notice that tumor coverage (115x) is higher than normal (84x). This is intentional in cancer studies because:

  • Tumor samples may have subclonal populations with low-frequency variants
  • Tumor purity varies: A deeper coverage is needed to detect variants in impure samples
  • Generally aim for 2-3x higher coverage in tumor than matched normal
